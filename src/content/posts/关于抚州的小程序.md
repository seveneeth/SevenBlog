# 《临川风物录》· 小程序介绍

一部关于抚州临川文化的**数字读本**。分人物、非遗、舆图三目，收录 4 位人物、5 项国家级非物质文化遗产、21 处实地坐标。

| | |
|---|---|
| 名称 | 临川风物录 |
| 副题 | 抚州地方文献的数字读本 |
| 范围 | 抚州全境 11 个县级行政区 |
| 形态 | 微信小程序（同一份源码亦可产出 H5） |
| 体量 | 主包 930 KB + 分包 962 KB |
| 技术 | uni-app（Vue 3）+ Vite |
| 服务端 | 无。收藏与浏览足迹只存本机，不联网、不上传 |

---

## 一、选题与立意

抚州，古临川郡。宋明之间，王安石、曾巩、陆九渊、汤显祖相继出于此；至今仍有傩班按谱起傩，有高腔在乡间戏台开锣。

本录想做的是把这些散在志书、名录与村落里的东西，编成一部**体例清楚、出处可查**的读本，而不是一堆图文拼贴。

**三目体例**

- **人物志**——立年表，生卒年与生平事迹编次
- **非遗志**——沿表演程式与流布村落编次，不写成泛泛的项目简介
- **舆图**——以实地坐标落点，县界与河道都用真实数据

**四条编纂原则**（写在内容档案的开头）

1. 年份、地名、名录批次均写可核对的说法，不写无出处的形容。
2. 历史纪年一律附公元年份；生卒年以通行说法为准。
3. 图像分「实景」与「艺术化」两类，前者标注发布单位与日期，后者如实注明非实录。
4. 图像无法说明拍摄信息时写「待补」，不作推定。

## 三、页面与功能

**开屏**：才子之乡 · 文化之邦两句逐字落墨，细线展开，落到「一卷临川梦 · 千年人文城」，点「走进抚州」入内。

**首页**

- 刊头：朱砂印章「临川」、题名「抚州」、八字副题与全录目数
- 卷首图版：四张实景轮播，每张下附图注与出处（可点入对应条目）
- 志乘撷录：王安石「天变不足畏，祖宗不足法，人言不足恤」，可换一条
- 目次：人物志 / 非遗志 / 舆图三张彩色卡
- 人物选刊：汤显祖特写，其余三位按生年编次列出
- 页脚：全部资料来源

**列表**：人物志按生年先后编次，左侧一条年份轴线；非遗志按国家级名录批次编次。

**详情**

- 人物：生平、行迹年表、著述与事功、原文、相关地点、图像资料
- 非遗：概况、表演程式、形态特征、流布村落、伴奏、名录、观赏、更多影像
- 图版可点开全屏查看，带图注与来源；相关条目互跳；条目所涉地点可直接跳到舆图并定位

**舆图**：可拖拽、可双指缩放，也备了点按缩放与复位；点位按县区折叠成索引，点条目即定位到地图；三类点位有图例区分；另有一条编者串起的「赣傩·戏曲采风线」，串联抚州境内傩与高腔的主要传承县，可随时显示或隐藏。

**我的**：收藏、浏览足迹（可清空）、文化徽章（初识临川 / 寻梦人 / 风物收藏家），以及一个只在本机生成的身份——昵称与头像都不上传，随时可退出登录。

底部导航四项：首页 / 人文 / 风物 / 我的。

## 四、设计

配色只用两个色族：**靛族**（靛青 → 紫檀）与**朱族**（朱砂 → 琥珀）。两族共用「紫檀」作桥接色——靛族渐变的终点、朱族渐变的起点都是它，所以两族相接处没有硬边，这是全录「融合」感的来源。

底色不逐块上色，而是用一条**连续铺底**横跨整块内容区，让底色缓慢推移，分区之间只靠细线分隔，避免出现拼色块。形状上：图片只收角，拱、叶、扇这类强形状只给按钮与色块。

正文字体内置**思源宋体子集**（按全录用字裁到 1140 字，随包发布），不依赖设备自带宋体，各端气质一致。

刊头那方印章用的是朱砂半透明底加一层中国风线框，压得住靛青刊头，又不像一块实心红。

动效克制：逐字落墨、细线展开、点按回弹，并适配系统的「减少动态效果」设置。

## 五、技术实现

- **一套源码两端**：uni-app（Vue 3）+ Vite，同时产出微信小程序与 H5。
- **分包**：主包只留开屏与首页，列表、详情、舆图、我的四页进分包；首页一出现就后台预下载分包，切换无等待感。主包 930 KB、分包 962 KB，均在微信建议值内。
- **舆图**：县界取自 DataV.GeoAtlas 公开标准界线，河道取自 OpenStreetMap 实测水系，点位为实地坐标；底图与点位数据由脚本生成，可回溯、可重算。

# 临川风物录

介绍抚州临川文化与风物的**纯前端**小程序。分人物志、非遗志、舆图三目：人物立年表，非遗按表演程式与流布村落编次，舆图以实地坐标落点。

没有服务端。收藏与浏览足迹只存在本机，登录只是在本机生成一个昵称与头像，不上传、不校验。

技术栈：uni-app（Vue 3）+ Vite，一份源码同时产出**微信小程序**与 **H5**。

## 跑起来

两条路径，**产物目录不一样**，别混着用：

| 方式             | 命令                                       | 产物目录                             |
| ---------------- | ------------------------------------------ | ------------------------------------ |
| 命令行 · 开发    | `npm run dev:mp-weixin`                    | `dist/dev/mp-weixin`                 |
| 命令行 · 发布    | `npm run build:mp-weixin`                  | `dist/build/mp-weixin`（上传用这个） |
| HBuilderX · 运行 | 运行 → 运行到小程序模拟器 → 微信开发者工具 | `unpackage/dist/dev/mp-weixin`       |
| H5               | `npm run dev:h5` / `npm run build:h5`      | `dist/dev/h5` / `dist/build/h5`      |

用微信开发者工具的「导入项目」指向**产物目录**（不是仓库根目录）——uni-app 会把 `app.json` 等小程序文件生成在那儿，根目录里没有。

`package.json` 里的脚本都带了 `UNI_INPUT_DIR=%CD%`：这个项目的源码就在根目录（没有 `src/`），必须显式告诉编译器输入目录在哪。

### 一个必须知道的坑

**改动 `pages.json` 的分包结构后，HBuilderX 要「停止运行」再「重新运行」。**

原因：分包要拷贝哪些静态目录（`<分包根>/static/**`），是 uni-app 的拷贝插件**在进程启动时**算好并缓存的。已经跑着的 dev 进程不会重新计算——它既不会补拷新分包的 `sub/static/`，也不会删掉已删除页面的旧产物。命令行 `npm run dev:mp-weixin` 同理，重启进程即可。

## 目录结构

```
pages/             主包页面：splash（开屏）、home（首页）
sub/               分包：list 列表 / detail 详情 / map 舆图 / mine 我的
  shared/          只被分包页面引用的模块（account、字体元信息）
  static/          只被分包用到的图片、点位数据
components/        自定义 TabBar
static/            主包静态资源：content.js、icons、图片
shared/            全局字体样式（serif-subset.css，由 App.vue 引入）
tools/             开发脚本，见下
tools/raw/         采集到的原始数据（GeoJSON、OSM、素材清单）
tools/out/         开发期对照图、体检截图
assets/            原始素材，不进包：incoming 原图、source-icons 图标包
dist/ unpackage/   构建产物
```

## 分包：为什么这么分，以及怎么改

微信建议主包小于 1.5 MB。当前（发布版）**主包 930 KB、分包 962 KB**。

- 主包只留开屏与首页；列表、详情、舆图、我的四页在分包 `sub` 下。
- `pages.json` 的 `preloadRule` 让首页一出现就后台预下载分包，点「人文 / 风物 / 我的」不会有等待感。

**图片归属规则（最容易踩的一条）**

> 主包里的资源，分包页面读得到；分包里的资源，**主包读不到**。

所以：首页轮播与刊头选刊用的图必须留在 `/static/`；只有列表、详情、我的会用到的图放 `/sub/static/`。`static/content.js` 顶部有三个路径助手来区分：

```js
const M  = (f) => '/static/assets/images/media/' + f      // 主包（首页要用）
const S  = (f) => '/sub/static/assets/images/media/' + f  // 分包
const SC = (f) => '/sub/static/assets/images/culture/' + f
```

**加一个新页面**

1. 放到 `sub/<名字>/index.vue`（目录层级与 `pages/x/` 相同，相对 import 不用改）
2. 在 `pages.json` 的 `subPackages[0].pages` 登记
3. 跳转写 `/sub/<名字>/index`；`components/TabBar.vue` 里的地址也要跟着改
4. 只被它用到的图放 `sub/static/assets/images/`，在 `content.js` 里用 `S()` / `SC()`

**改完务必跑一遍体检**（见文末），它会核对每条资源引用在产物里是否真的存在——分包之后最容易出的事就是「图搬了、引用忘了改」。

## 设计系统

配色、形状、动效的变量全在 `App.vue` 的 `<style>` 里，文件顶部有一段注释说明配色逻辑，改样式前先读它。

- **两族配色**：靛族（靛青 → 紫檀）与朱族（朱砂 → 琥珀），两族共用「紫檀 `#5c3a55`」做桥接色——靛族渐变的终点、朱族渐变的起点都是它，所以两族相接处没有硬边。
- **连续铺底**：`--wash-*` 横跨整块内容区让底色缓慢推移，分区之间只靠细线分隔，避免拼色块。
- **通用类**：`.shape-*` 形状、`.tap` / `.pressable` 点按反馈、`.rise` / `.fade` / `.pop` / `.zoom` 入场动效，都已适配 `prefers-reduced-motion`。
- **rpx 不要写进自定义属性**：H5 会把 rpx 编译成 rem、小程序保持 rpx，两端解析不一致。rpx 一律写在具体属性上。
- **图标**：`static/icons/` 下统一为单色墨稿（`#17233a`），用 `filter: brightness(0) invert(1)` 反白。
- **字体**：思源宋体子集（1140 字、7 片）随包内置，避免各设备回退到不同系统宋体。`@font-face` 在主包 `shared/serif-subset.css`，元信息在分包 `sub/shared/serif-subset.js`。

改完样式跑一次 `node tools/check-tokens.js`：变量没定义时属性会静默失效（比如背景变透明），肉眼很难发现。

## 内容与数据

| 文件                      | 作用                                                         |
| ------------------------- | ------------------------------------------------------------ |
| `static/content.js`       | 人物、非遗、首页轮播、资料来源。改文案/图注改这里            |
| `sub/static/map-data.js`  | 舆图点位与投影参数，**由 `tools/build-map.js` 生成，别手改** |
| `shared/serif-subset.css` | 字体 `@font-face`（base64），由 `tools/build-font.js` 生成   |

## 已知限制

**「图片和音频资源大小应不超过 200 K」这条代码质量规则过不了。** 官方口径是代码包里所有图片、音频**加起来**不超过 200 KB（建议把大图放 CDN、用 URL 引入），而本项目包内图片合计约 1.2 MB（29 张照片 + 1 张舆图底图 SVG）——照片就是内容本身。要让它变绿只有把照片远程化（需要备案域名并配置 request 合法域名），代价是这个纯前端、离线可看的小程序从此依赖网络。该规则是【建议】级，**不阻塞上传与发布**。

其余几条（主包大小、按需注入、主包内无仅被分包依赖的 JS）均已通过。曾试过一档更狠的压缩（560px / q62，图片 1213 → 767 KB），画质评审后弃用，参数已回调为原值。
