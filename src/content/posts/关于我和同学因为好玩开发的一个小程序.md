# 梦幻衣橱 · ChangeCloseGame

事情是这样的，我的一个朋友用Trae做了一个换装小游戏。某天我突发奇想把它做成微信小程序（因为我那时候正在学），感觉最困难的还是debug，bug太多了。。。  

一个程序化换装小游戏。仓库内包含三部分：

| 目录 | 说明 |
| --- | --- |
| `web-prototype/` | **原始浏览器原型**（纯 DOM/SVG，直接双击 `index` 需本地起 HTTP 服务）。原 `app.js / data.js / render.js / features.js / style.css` 均保留于此。 |
| `uni-app/` | **uni-app 版**（Vue2 单页），保留完整玩法，角色用现有 SVG 代码渲染到 `<image>`（H5/App）或 `<canvas type="2d">`（微信小程序）。H5 / App / mp-weixin 均可运行。 |
| `backend/` | **FastAPI 后端**：云存档同步 + 成就/统计。 |

> 说明：H5 / App 端用 SVG `<image>`（视觉 100% 还原、改动最小）；微信小程序端 `<image>` 对 SVG data-URI 支持不可靠（真机亦无 `btoa`），因此 mp-weixin 走内置 Canvas 渲染层（`svg2canvas.js` + canvas 组件），同一份 `avatarSVG` 几何。运行与注意事项见 [`uni-app/README.md`](uni-app/README.md)。

## 快速开始（uni-app 版）

用 **HBuilderX** 打开 `uni-app/` 目录 → 运行 → 运行到浏览器（H5）即可玩；无需 npm。

详细说明见 [`uni-app/README.md`](uni-app/README.md)。

## 玩法

游戏为程序化换装体验，界面左侧提供功能分类栏，涵盖角色本体、发型、发色、肤色、瞳色、眼型以及各类服饰分组。点击对应分类后，底部面板会展示该分类下全部可用单品，点击单品即可即时穿戴，角色形象实时刷新预览。

系统内置穿搭互斥校验逻辑，自动处理服饰冲突：连衣裙会与上衣、下装、半裙互斥，裙子与裤子不能同时穿戴，从底层规避服饰穿模、图层错乱问题，保证画面展示合理。

除手动挑选部件外，可使用随机搭配功能，一键自动生成一套完整人物造型，快速获得新奇穿搭方案。搭配完成后可以触发穿搭评分，系统会根据部件组合给出搭配评价。

游戏具备完整收集与存档体系：游玩过程会解锁各类成就，记录玩家搭配行为数据；既支持本地存档保存进度，接入后端服务后还可开启云端同步，更换设备也不会丢失数据。专属衣橱可保存至多8套自制搭配方案，方便快速切换已保存造型；同时支持作品分享，附带分享计数统计，可将自己设计的人物穿搭对外分享。

全部人物形象均由代码程序化生成，数据源移植自浏览器原型，依靠 SVG 几何数据驱动渲染，H5/App 使用 SVG 渲染，微信小程序则通过 Canvas 完成绘制，多端下人物部件、造型逻辑完全统一。
